# Constitution of the canon

Governance for [`AXIOMS.md`](AXIOMS.md) — the rules that keep the axiom set closed, clean, and honestly maintained.

**Consumer: whoever amends the canon.** This is not law for the finite actor; it is law for the *editor* of the law. The canon itself does not know who reads it — which is exactly why these rules live here, not there. Governance references the law it governs; the law never references its own upkeep.

---

## Admission — what may enter the set

- **Residual-force test.** A new axiom must add a force the union of the others does not — remove it and a real gap appears. No residue → it is a corollary or a fuel property, not an axiom.

## Hygiene — what the set must always satisfy

- **Consistent** — no pair of axioms contradicts.
- **Independent** — each carries a residual force (the admission test, held standing).
- **Frame-translates** — each holds across ≥3 of person / career / AI agent / team.

## Self-application (dogfood)

The canon is itself a finite-actor artifact, so it must obey its own axioms — one home per truth (SSOT), one whole goal (Atomic), declared edges (Boundary), no ornament (Outcome-Driven). If the document violates an axiom, the document is wrong: fix the document, not the axiom.

## Boundary of the canon

`AXIOMS.md` holds substrate-neutral law only — no frame projections, examples, or named consumers; those live in the consumer's repo. Governance lives here, at the repo. The canon and its constitution are different concerns with different readers, kept in different homes.

## Amendment

Change the canon only by deliberate, versioned amendment — never silent drift.
